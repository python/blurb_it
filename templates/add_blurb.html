Add a NEWS entry

The CPython GitHub issue number.
The CPython GitHub pull request number.
Optional. The CVE identifier (CVE-YYYY-NNNN) for this security fix.

The entry becomes part of the changelog, whose readers are mainly users, not core developers. Most of them will not open the issue or the diff, so the entry must stand alone. Keep it to one or two sentences.

  • Start with a verb in the imperative mood that says what kind of change it is: Fix, Add, Remove, Deprecate, Allow, Raise.
  • Name what changed using inline markup such as :func:, :class: or :mod:, so readers can jump to the documentation.
  • Say what a user will notice, and under what conditions. Then stop.
  • Leave out implementation details, how the problem was found, tests that were added, and phrases such as "this PR".
  • Write valid reStructuredText with no leading - and no issue number, which is already part of the file name.
  • Attribution is optional and goes in a final sentence of the form Patch by Jane Doe.

Example:
Fix :class:`logging.handlers.TimedRotatingFileHandler` permanently stopping rollover after a rollover failed or its backup file already existed, for example at a DST change.

See How to write a NEWS entry in the devguide for the full guidance and more examples.

One or two sentences of reStructuredText. See the guide above.
